# رفع خطای بوت 0x000000ED ویندوز XP — بعد از جابه‌جایی دیسک به سخت‌افزار جدید

**بوت‌گیری — و سرِ عقل آوردن — یک ویندوز XP پیر بعد از اینکه دیسکش روی سخت‌افزار جدید افتاد.**
بدون نصب مجدد، بدون کرک فعال‌سازی، بدون سیکل بوت‌های بی‌پایان. در میدان عمل تست شده روی گیگابایت GA-M720-ES3 (چیپ‌ست NVIDIA nForce 720a).

```
STOP: 0x000000ED (0xFFFFFAD3, 0xC0000015, ...)      <- حتی بالا نمیاد
"Windows needs to be activated"                      <- حتی دهنش هم بسته نمیشه
```

این مخزن، راهنمای کامل و تست‌شده برای هر دو مشکل بالاست.

## مشکل

یک سیستم قدیمی می‌میرد. دیسک XP را درمی‌آورید و به یک برد جدید وصل می‌کنید. نتیجه:

| نشانه | علت |
|---|---|
| `STOP 0x000000ED` / `0xC0000015` موقع بوت | NTFS نمی‌تواند نوشتن‌های موقع بوت را کامل کند. یا قفل نوشتن سمت هاست است (مرحله ۳) یا کنترلر SATA جدید توسط هیچ درایوری قبول نشده (مرحله ۴). |
| بوت می‌شود ولی فعال‌سازی می‌خواهد | WPA با تغییر سخت‌افزار به هم می‌ریزد. |
| موقع هر بوت chkdsk اجرا می‌شود | فلگ Dirty پارتیشن از خاموش‌کردن‌های ناگهانی. |
| کندی / مشکل تایمر | بردهای nForce + منبع تایمر خراب (با `/usepmtimer` حل می‌شود). |

همه کارهای زیر **آفلاین و از روی یک هاست ویندوز ۱۰/۱۱** انجام می‌شود، مگر جاهایی که مشخصاً فرق دارد.

## روش کار

1. قبل از هر دست‌کاری، بکاپ از بوت‌سکتور بگیرید.
2. با تست در VM ثابت کنید که نصب بوت‌پذیر است (با یک نکته مهم سمت هاست).
3. فایل‌سیستم و رجیستری را طوری وصله بزنید که چیپ‌ست جدید بتواند دیسک را سوار کند (حالت IDE/Legacy + درایور IDE جنریک).
4. بوت کنید و با یک کد فعال‌سازی معتبر رمزنگاری‌شده فعال‌سازی کنید (بدون کرک).
5. همه آثار تشخیصی را تمیز کنید.

## پیش‌نیازها

- هاست ویندوز ۱۰/۱۱ با پاورشل (ادمین).
- دیسک XP به هاست وصل باشد (داک USB یا SATA).
- حرف درایو پارتیشن سیستم XP (در این راهنما: `F:`).
- حدود یک ساعت وقت و دستِ ثابت.
- **نکته بایوس:** SATA برد جدید باید در حالت **IDE/Legacy** باشد (نه AHCI و نه RAID). این راهنما برای همین حالت است.

## ایمنی اول

- نوشتن سکتور خام می‌تواند فایل‌سیستم را نابود کند. **همیشه اول اسکریپت بکاپ را اجرا کنید.**
- فایل بکاپ `.bin` را تا چند بار بوت موفق روی سخت‌افزار واقعی نگه دارید.
- هرگز وقتی حجم (Volume) آنلاین/مونت شده است نوشتن خام انجام ندهید — ویندوز نوشتن را رد می‌کند. اول دیسک را آفلاین کنید.
- هر وصله را با خواندن دوباره بررسی کنید (همه اسکریپت‌ها همین کار را می‌کنند).
- `diskpart` + `clean` روی دیسک اشتباه یعنی نابودی هفته‌تان. قبل از هر کار `Get-Disk` را دوباره چک کنید.

## مرحله ۱ — جمع‌آوری اطلاعات

دیسک و پارتیشن‌ها را شناسایی کنید و هندسه پارتیشن سیستم XP را یادداشت کنید:

```powershell
Get-Disk | Format-Table Number, FriendlyName, Size, PartitionStyle
Get-Partition -DiskNumber <N> | Format-Table PartitionNumber, DriveLetter, Type, Size
Get-Volume | Format-Table DriveLetter, FileSystemLabel, FileSystem, HealthStatus, Size
```

یادداشت کنید: اندازه پارتیشن سیستم به بایت، بایت‌برسکتور (معمولاً ۵۱۲)، سکتوربرکلاستر (معمولاً ۸ برای NTFS).

فلگ Dirty و تنظیمات بوت را چک کنید:

```powershell
fsutil dirty query F:
type F:\boot.ini
```

## مرحله ۳ — تشخیص با VM (و تله قفل نوشتن 0xED)

دیسک فیزیکی را به VM وصل کنید (VMware rawdisk / VirtualBox raw VMDK / Hyper-V pass-through) و XP را آنجا بوت کنید. اینطوری بدون ریبوت‌کردن ماشین فیزیکی، روی راه‌حل‌ها تکرار و خطا می‌کنید.

### تله‌ای که بهش خوردیم (با تست ایزوله ثابت شد)

- **بوت A (حجم OFFLINE روی هاست):** XP تا دسکتاپ بالا می‌آید. نوشتن‌ها موفق.
- **بوت B (حجم ONLINE/مونت‌شده روی هاست):** همان دیسک و همان وصله‌ها → `STOP 0x000000ED, param2 0xC0000015`.

**علت اصلی:** وقتی دیسک به هاست ویندوز وصل است، یک حجم NTFS *آنلاین* با قفل نوشتن انحصاری نگه داشته می‌شود. نوشتن‌های موقع بوتِ XP شکست می‌خورند → 0xED. این مشکل «VM خراب است» نیست؛ مشکل قفل‌کردن دیسک توسط هاست است.

**قانون:** قبل از بوت VM، دیسک را روی هاست آفلاین کنید:

```powershell
Set-Disk -Number <N> -IsOffline $true
# (بعد از تست: Set-Disk -Number <N> -IsOffline $false)
```

### اگر با دیسک آفلاین هم 0xED ماند

فیلد `TotalSectors64` بوت‌سکتور NTFS (آفست `0x28`) ممکن است صفر یا قدیمی باشد (مثلاً از یک نصب FAT کپی شده یا هندسه نیمه‌نوشته). در این صورت XP اندازه حجم را اشتباه می‌خواند و فایل‌هایش را پیدا نمی‌کند.

```powershell
.\scripts\patch_bpb_sectors.ps1 -DriveLetter F
```

اسکریپت مقدار فعلی و مورد انتظار را چاپ می‌کند و وصله می‌زند (مقدار مورد انتظار = اندازه حجم ÷ بایت‌برسکتور، خودکار حساب می‌شود) و نتیجه را با خواندن دوباره تأیید می‌کند.

**رسیدن VM به دسکتاپ → نصب سالم است.** مشکل باقی‌مانده در بوت فیزیکی، درایورهای SATA است → مرحله ۴.

## مرحله ۴ — جراحی رجیستری برای چیپ‌ست جدید

XP روی برد واقعی بوت نمی‌شود چون استک درایور قدیمی کنترلر SATA جدید را نمی‌شناسد. راه‌حل دو بخشی، آفلاین روی hiveها:

1. **Critical Device Database (CDDB):** به درایور IDE جنریک (`pciide`) بگویید هر کنترلر در حالت IDE را قبول کند. کنترلر nForce 720a SATA در حالت IDE با کلاس PCI کد `0101` (کنترلر IDE) شناسایی می‌شود، پس اضافه کنید:

   ```
   HKLM\SYSTEM\ControlSet00X\Control\CriticalDeviceDatabase\pci#cc_0101
       Service   = "pciide"
       ClassGUID = "{4D36E96A-E325-11CE-BFC1-08002BE10318}"   (کلاس SCSIAdapter)
   ```

2. **سرویس‌ها:** استک IDE باید موقع بوت لود شود (`Start = 0`):

   ```
   HKLM\SYSTEM\ControlSet00X\Services\intelide  Start = 0
   HKLM\SYSTEM\ControlSet00X\Services\pciide    Start = 0
   ```

با یک دستور هر دو انجام می‌شود (به `ControlSet001` و `ControlSet002` اضافه می‌کند و hiveها را تمیز لود/آنلود می‌کند):

```powershell
.\scripts\apply_registry_fixes.ps1 -SystemDriveLetter F
```

> روی برد مقصد چک کنید: کنترلر SATA باید با کلاس `0101` و درایور IDE *جنریک* بایند شود — نه سرویس `nvata`/`nvgts`/`nvraid`، نه حالت AHCI/RAID.

### شناسایی چیزی که برد شما شناسایی می‌کند

از هر ویندوزی که روی برد مقصد اجرا می‌شود، دستگاه‌های PCI را لیست کنید و کلاس کد کنترلر SATA را چک کنید:

```powershell
wmic path Win32_PnPEntity where "DeviceID like 'PCI%'" get DeviceID, Name /format:list
```

مقادیر مرجع (nForce 720a، حالت IDE/Legacy، تست‌شده در میدان):

```
PCI\VEN_10DE&DEV_0759  -> NVIDIA nForce 720a/730a SATA   (کلاس 0101، کنترلر IDE)
PCI\VEN_10DE&DEV_0AD0  -> NVIDIA nForce 720a PATA        (کلاس 0101، کنترلر IDE)
```

هر دو به درایور جنریک «Standard Dual Channel PCI IDE Controller» (`pci\cc_0101`) بایند می‌شوند و **هیچ** سرویس `nvata`/`nvgts`/`nvraid` وجود ندارد. دقیقاً همین وضعیت است که ورودی CDDB بالا برایش است.

مرجع کلاس کد: `0101` = کنترلر IDE (این راهنما)، `0106` = AHCI، `0104` = RAID. اگر `0106`/`0104` دیدید، برد را در بایوس به حالت IDE/Legacy ببرید — این راهنما تزریق درایور AHCI/RAID را پوشش نمی‌دهد.

## مرحله ۵ — فعال‌سازی به روش درست

تغییر سخت‌افزار WPA را به هم می‌ریزد و پیام فعال‌سازی می‌آید. دو راه برای ساکت‌کردنش هست — **فقط یکی دائمی است:**

### ❌ روش فایل reg جادویی (نکنید)

تنظیم `OOBETimer` به مقدار معروف `FFD571D68B6A8D6FD53393FD` + یک `DigitalProductId` «وصله‌شده» **روی این سخت‌افزار دوام نمی‌آورد** (دوبار تست کردیم):

1. بوت → WPA یک `OOBETimer` تازه می‌سازد → حالت برمی‌گردد به قبل.
2. اگر کپی داخل hive سیستم (SYSTEM) را هم وصله بزنید → WPA حالت را **corrupted** اعلام می‌کند و سر صفحه خطا گیر می‌کند.

این مسیر روی بردهای nForce با ساعت CMOS مرده بن‌بست است.

### ✅ روش Confirmation ID (دائمی، بدون کرک)

فعال‌سازی تلفنی ویندوز از روی **Installation ID** یک **Confirmation ID** می‌سازد. این الگوریتم (ریاضیات hyperelliptic curves داخل `licdll.dll`) مهندسی معکوس شده و به صورت ابزار متن‌باز پیاده شده است. وارد کردن یک Confirmation ID معتبر یعنی فعال‌سازی *واقعی* — WPA برای همیشه قبولش می‌کند؛ نه برگشت، نه پیام، نه بالون.

1. سیستم را بوت کنید → ویزارد فعال‌سازی **Installation ID** را نشان می‌دهد (۵۴ رقم، ۹ گروه ۶تایی، مثلاً `123456-789012-345678-...`).
2. **Confirmation ID** را با یکی از این ابزارها بسازید (متن‌باز، روی هاست یا روی خود XP اجرا می‌شود):
   - [Alex313031/xp_activate32](https://github.com/Alex313031/xp_activate32) — گرافیکی، خروجی آماده `.exe` دارد
   - [Endermanch/XPConfirmationIDKeygen](https://github.com/Endermanch/XPConfirmationIDKeygen) — نسخه اصلی
3. Confirmation ID را در ویزارد وارد کنید → **فعال‌سازی دائمی.**

این ابزار Confirmation ID را **محلی** و از روی Installation ID محاسبه می‌کند — نه به ماشین XP نیاز دارد، نه به سرورهای مایکروسافت؛ پس روی هاست هم راحت کار می‌کند. دکمه «activate/deposit» داخل GUI فقط روی خود XP کار می‌کند (با `licdll.dll` محلی حرف می‌زند)؛ روی هاست فقط کد تولیدشده را در ویزارد فعال‌سازی وارد کنید.

فقط برای سیستم‌هایی استفاده کنید که مالکش هستید و لایسنس دارید.

## مرحله ۶ — تمیزکاری

وقتی دستگاه پایدار شد:

- **boot.ini** — فلگ‌های دیباگ باقی‌مانده از مرحله تشخیص را بردارید:
  ```powershell
  .\scripts\clean_boot_ini.ps1 -DriveLetter F
  ```
  `/bootlog` و `/SOS` را حذف می‌کند؛ `/fastdetect` و `/usepmtimer` را نگه می‌دارد (این دومی مشکل تایمر بردهای nForce/AMD را حل می‌کند).

- **فلگ Dirty** — اگر حجم Dirty است، تا پاک‌شدنش chkdsk موقع هر بوت اجرا می‌شود:
  ```powershell
  .\scripts\check_volume_state.ps1
  chkdsk F: /f        # فقط اگر Dirty گزارش داد
  ```

- فایل‌های باقی‌مانده را پاک کنید: `ntbtlog.txt` (فقط وقتی `/bootlog` ست باشد ساخته می‌شود)، VHDهای تست و غیره.

- **بررسی نهایی همه‌چیز** با یک دستور:
  ```powershell
  .\scripts\verify_fixes.ps1 -DriveLetter F
  ```

## بازگشت (Rollback)

هر مرحله برگشت‌پذیر است:

- **بوت‌سکتور / BPB** → برگرداندن از بکاپ:
  ```powershell
  .\scripts\restore_bootsector.ps1 -DriveLetter F -BackupPath backups\bootsector_<timestamp>.bin
  ```
- **اصلاحات رجیستری** → `ControlSet00X\Control\CriticalDeviceDatabase\pci#cc_0101` را حذف کنید و مقادیر `Start` سرویس‌های `intelide`/`pciide` را به حالت اول برگردانید (قبل از اجرای اسکریپت، مقادیر قبلی را یادداشت کنید).
- **فعال‌سازی** → فعال‌سازی واقعی است؛ چیزی برای بازگشت نیست. اگر به‌جایش از reg-hack استفاده کرده بودید و گیر کرده‌اید، به سوالات پرتکرار مراجعه کنید.

## ضمیمه — اتصال دیسک فیزیکی به VM

برای اینکه XP از روی همان نصب فیزیکی بوت شود، به یک دیسک raw (pass-through) در VM نیاز دارید. دیسک باید به هاست وصل باشد:

**VirtualBox** (به‌عنوان ادمین — اول دیسک را آفلاین/آنمونت کنید):

```powershell
VBoxManage internalcommands createrawvmdk `
    -filename "C:\vm\xpdisk.vmdk" -rawdisk \\.\PhysicalDrive<N>
```

بعد `xpdisk.vmdk` را به‌عنوان دیسک SATA/IDE به VM اضافه کنید. وقتی VM در حال اجراست، اجازه ندهید هاست حجم‌های XP را مونت کند (مرحله ۳).

**VMware Workstation:** فایل دیسکریپتور raw-disk `xpdisk.vmdk` را با هندسه دیسک فیزیکی بسازید:

```
# Disk DescriptorFile
version=1
CID=ffffffff
parentCID=ffffffff
createType="fullDevice"

# Extent description
RW 3907029168 FLAT "\\.\PhysicalDrive<N>" 0

# The Disk Data Base
ddb.virtualHWVersion = "7"
ddb.geometry.cylinders = "<cylinders>"
ddb.geometry.heads = "16"
ddb.geometry.sectors = "63"
```

(اندازه extent و هندسه را با دیسک خودتان هماهنگ کنید: `Get-Disk` + `Get-Partition` اندازه را نشان می‌دهند؛ `heads=16, sectors=63`، `cylinders = size / 512 / 63 / 16`.) بعد `.vmdk` را به VM اضافه کنید.

**Hyper-V:** `Add-VMHardDiskDrive -VMName <vm> -Path \\.\PhysicalDrive<N>` (pass-through).

در همه حالات: VM باید **همان** پارتیشنی را بوت کند که برد واقعی بوت می‌کند. در طول بوت‌های VM دیسک را روی هاست **آفلاین** نگه دارید (`Set-Disk -Number <N> -IsOffline $true`).

## سوالات پرتکرار

**س: با دیسک آفلاین در VM باز هم 0xED می‌گیرم.**
ج: BPB را وصله بزنید (`patch_bpb_sectors.ps1`). اگر درست بود، چک کنید `ntldr`/`NTDETECT.COM` موجودند و مسیر ARC در boot.ini با پارتیشن واقعی یکی است (`partition(1)` و...).

**س: بوت می‌شود ولی «It's now safe to turn off your computer» می‌آید.**
ج: این نصب با HAL غیر ACPI («Standard PC») از ماشین قبلی بالا آمده. تعویض HAL به ACPI از نظر تئوری ممکن است، ولی روی این بیلد لاغر حتی با `hal.inf` و ترفندهای `/hal=` و `/kernel=` در boot.ini بلواسکرین داد؛ به همین دلیل عمداً در این راهنما نیست. ماشین درست کار می‌کند؛ فقط نمی‌تواند خودکار خاموش شود.

**س: پیام فعال‌سازی برمی‌گردد؟**
ج: با Confirmation ID واقعی — نه. تمام نکته مرحله ۵ این است که WPA یک فعال‌سازی معتبر ذخیره می‌کند.

**س: موقع هر بوت chkdsk اجرا می‌شود.**
ج: فلگ Dirty — مرحله ۶.

**س: می‌شود روی برد AHCI/RAID استفاده کرد؟**
ج: وصله رجیستری برای حالت IDE/Legacy است (کلاس 0101). برای AHCI باید درایور AHCI برد را داخل نصب قالب کنید که داستان سخت‌تری است.

**س: برد من nForce نیست؛ اینتل یا AMD است.**
ج: مراحل به چیپ‌ست وابسته نیستند؛ فقط نکته `/usepmtimer` و جزئیات ورودی CDDB فرق می‌کند (کلاس کد کنترلر خودتان را چک کنید).

**س: اول reg-hack (OOBETimer/DPID) را امتحان کردم و حالا XP روی صفحه خطای فعال‌سازی گیر کرده.**
ج: هک را برگردانید: hiveها را از بکاپ قبل از هک بازیابی کنید (یا `DigitalProductId`/`OOBETimer` را به مقادیر اصلی برگردانید و `wpa.dbl` را حذف کنید)، یک بار بوت کنید تا WPA حالت تمیز بسازد، بعد از مسیر Confirmation ID در مرحله ۵ بروید. با ماشین وضعیت نجنگید — با یک فعال‌سازی واقعی جایگزینش کنید.

**س: حتی بعد از فعال‌سازی بالون «your Windows is not genuine» می‌آید.**
ج: این WGA است؛ چک جداگانه‌ای روی کلید محصول است (نه روی وضعیت WPA). با `MGADiag.exe` مایکروسافت (ابزار امضاشده) بررسی کنید. با فعال‌سازی واقعی و کلید OEM قانونی معمولاً خودش درست می‌شود؛ اگر ماند، کلید خودش در لیست بلاک است و فقط یک کلید مجاز دیگر حلش می‌کند.

**س: آیا keygen باید روی خود ماشین XP اجرا شود؟**
ج: نه — Confirmation ID را محلی و از روی Installation ID روی هر ویندوزی حساب می‌کند. فقط دکمه «activate/deposit» داخل GUI به XP نیاز دارد (در `licdll.dll` محلی می‌نویسد)؛ به همین سادگی می‌توانید کد تولیدشده را در ویزارد فعال‌سازی تایپ کنید.

**س: نمی‌دانم برد من در چه حالتی SATA است.**
ج: کوئری wmic از مرحله ۴ را روی برد اجرا کنید: کلاس `0101` = IDE/Legacy (این راهنما جواب می‌دهد)، `0106` = AHCI (نیاز به تزریق درایور دارد — پوشش داده نشده)، `0104` = RAID (پوشش داده نشده).
