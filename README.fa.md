# رفع خطای بوت 0x000000ED ویندوز XP — بعد از جابه‌جایی دیسک به سخت‌افزار جدید

**راهنمای بوت‌کردن یک نصب قدیمی ویندوز XP پس از انتقال دیسک به سخت‌افزار جدید — بدون نصب مجدد، بدون کرک فعال‌سازی، بدون چرخه بوت‌های بی‌نتیجه.**

این راهنما در عمل روی یک برد Gigabyte GA-M720-ES3 (چیپ‌ست NVIDIA nForce 720a) تست شده است.

```
STOP: 0x000000ED (0xFFFFFAD3, 0xC0000015, ...)      <- اصلاً بوت نمی‌شود
"Windows needs to be activated"                      <- پیام فعال‌سازی دائماً ظاهر می‌شود
```

این مخزن، راهنمای کامل و تست‌شده برای حل همین دو مشکل است.

## مشکل

یک سیستم قدیمی از کار می‌افتد. دیسک XP را خارج کرده و به یک برد جدید وصل می‌کنید. نتیجه:

| نشانه | علت |
|---|---|
| `STOP 0x000000ED` / `0xC0000015` هنگام بوت | NTFS نمی‌تواند نوشتن‌های زمان بوت را کامل کند؛ یا قفل نوشتن سمت هاست است (مرحله ۳) یا کنترلر SATA جدید توسط هیچ درایوری پشتیبانی نمی‌شود (مرحله ۴). |
| بوت انجام می‌شود اما فعال‌سازی درخواست می‌شود | WPA بر اثر تغییر سخت‌افزار به هم می‌ریزد. |
| هنگام هر بوت chkdsk اجرا می‌شود | فلگ Dirty پارتیشن بر اثر خاموش‌کردن‌های ناگهانی. |
| کندی / مشکل تایمر | بردهای nForce + منبع تایمر نامناسب (با `/usepmtimer` حل می‌شود). |

تمام عملیات زیر **آفلاین و از روی یک هاست ویندوز ۱۰/۱۱** انجام می‌شود، مگر جاهایی که مشخصاً ذکر شده است.

## روش کار

1. قبل از هر دست‌کاری، از بوت‌سکتور بکاپ بگیرید.
2. با تست در VM ثابت کنید که نصب بوت‌پذیر است (با یک نکته مهم سمت هاست).
3. فایل‌سیستم و رجیستری را طوری وصله بزنید که چیپ‌ست جدید بتواند دیسک را مدیریت کند (حالت IDE/Legacy + درایور IDE جنریک).
4. سیستم را بوت کنید و با یک Confirmation ID معتبر رمزنگاری‌شده فعال‌سازی کنید (بدون کرک).
5. همه آثار تشخیصی را تمیز کنید.

## پیش‌نیازها

- هاست ویندوز ۱۰/۱۱ با PowerShell (دسترسی ادمین).
- دیسک XP به هاست متصل باشد (داک USB یا SATA).
- حرف درایو پارتیشن سیستم XP (در این راهنما: `F:`).
- حدود یک ساعت زمان و دقت کافی.
- **نکته بایوس:** حالت SATA برد جدید باید **IDE/Legacy** باشد (نه AHCI و نه RAID). این راهنما برای همین حالت نوشته شده است.

## ایمنی اول

- نوشتن سکتور خام می‌تواند فایل‌سیستم را نابود کند. **همیشه ابتدا اسکریپت بکاپ را اجرا کنید.**
- فایل بکاپ `.bin` را تا چند بار بوت موفق روی سخت‌افزار واقعی نگه دارید.
- هرگز روی حجمی که آنلاین/مونت شده است نوشتن خام انجام ندهید — ویندوز چنین نوشتنی را رد می‌کند. ابتدا دیسک را آفلاین کنید.
- هر وصله را با خواندن دوباره سکتورها بررسی کنید (همه اسکریپت‌ها همین کار را انجام می‌دهند).
- `diskpart` + `clean` روی دیسک اشتباه یعنی نابودی کامل داده‌ها. قبل از هر کار، `Get-Disk` را دوباره بررسی کنید.

## مرحله ۱ — جمع‌آوری اطلاعات

دیسک و پارتیشن‌ها را شناسایی کنید و هندسه پارتیشن سیستم XP را یادداشت کنید:

```powershell
Get-Disk | Format-Table Number, FriendlyName, Size, PartitionStyle
Get-Partition -DiskNumber <N> | Format-Table PartitionNumber, DriveLetter, Type, Size
Get-Volume | Format-Table DriveLetter, FileSystemLabel, FileSystem, HealthStatus, Size
```

این موارد را یادداشت کنید: اندازه پارتیشن سیستم به بایت، بایت‌برسکتور (معمولاً ۵۱۲)، سکتوربرکلاستر (معمولاً ۸ برای NTFS).

فلگ Dirty و تنظیمات بوت را بررسی کنید:

```powershell
fsutil dirty query F:
type F:\boot.ini
```

## مرحله ۲ — بکاپ از بوت‌سکتور

```powershell
.\scripts\backup_bootsector.ps1 -DriveLetter F
```

این اسکریپت فایل `backups\bootsector_<timestamp>.bin` (۵۱۲ بایت؛ بوت‌سکتور حجم / BPB) را می‌سازد و SHA256 آن را چاپ می‌کند. این فایل را تا پایدار شدن کامل دستگاه نگه دارید.

## مرحله ۳ — تشخیص با VM (و تله قفل نوشتن 0xED)

دیسک فیزیکی را به VM متصل کنید (VMware rawdisk / VirtualBox raw VMDK / Hyper-V pass-through — جزئیات در ضمیمه) و XP را آنجا بوت کنید. به این ترتیب بدون ریبوت‌های مکرر ماشین فیزیکی، می‌توانید روی راه‌حل‌ها تکرار و خطا کنید.

### تله‌ای که در عمل به آن برخوردیم

- **بوت A (حجم OFFLINE روی هاست):** XP تا دسکتاپ بالا می‌آید؛ نوشتن‌ها موفق است.
- **بوت B (حجم ONLINE/مونت‌شده روی هاست):** همان دیسک و همان وصله‌ها → `STOP 0x000000ED, param2 0xC0000015`.

**علت اصلی:** وقتی دیسک به هاست ویندوز متصل است، یک حجم NTFS *آنلاین* با قفل نوشتن انحصاری نگه داشته می‌شود. در نتیجه نوشتن‌های زمان بوتِ XP شکست می‌خورد و خطای 0xED رخ می‌دهد. این مشکلِ VM نیست؛ مشکلِ قفل‌شدن دیسک توسط هاست است.

**قانون:** قبل از بوت VM، دیسک را روی هاست آفلاین کنید:

```powershell
Set-Disk -Number <N> -IsOffline $true
# بعد از اتمام تست: Set-Disk -Number <N> -IsOffline $false
```

### اگر با دیسک آفلاین نیز 0xED باقی ماند

فیلد `TotalSectors64` بوت‌سکتور NTFS (آفست `0x28`) ممکن است صفر یا قدیمی باشد (مثلاً از یک نصب FAT کپی شده یا هندسه نیمه‌نوشته). در این صورت XP اندازه حجم را اشتباه می‌خواند و فایل‌هایش را پیدا نمی‌کند.

```powershell
.\scripts\patch_bpb_sectors.ps1 -DriveLetter F
```

اسکریپت مقدار فعلی و مورد انتظار را چاپ می‌کند، در صورت نیاز وصله می‌زند (مقدار مورد انتظار = اندازه حجم ÷ بایت‌برسکتور، به‌صورت خودکار محاسبه می‌شود) و نتیجه را با خواندن دوباره تأیید می‌کند.

**رسیدن VM به دسکتاپ → نصب سالم است.** مشکل باقی‌مانده در بوت فیزیکی، درایورهای SATA است → مرحله ۴.

## مرحله ۴ — جراحی رجیستری برای چیپ‌ست جدید

XP روی برد واقعی بوت نمی‌شود، زیرا استک درایور قدیمی کنترلر SATA جدید را نمی‌شناسد. راه‌حل دو بخشی است و به‌صورت آفلاین روی hiveها انجام می‌شود:

1. **Critical Device Database (CDDB):** به درایور IDE جنریک (`pciide`) بگویید هر کنترلر در حالت IDE را بپذیرد. کنترلر SATA برد nForce 720a در حالت IDE با کلاس PCI کد `0101` (کنترلر IDE) شناسایی می‌شود؛ پس این ورودی را اضافه کنید:

   ```
   HKLM\SYSTEM\ControlSet00X\Control\CriticalDeviceDatabase\pci#cc_0101
       Service   = "pciide"
       ClassGUID = "{4D36E96A-E325-11CE-BFC1-08002BE10318}"   (کلاس SCSIAdapter)
   ```

2. **سرویس‌ها:** استک IDE باید هنگام بوت بارگذاری شود (`Start = 0`):

   ```
   HKLM\SYSTEM\ControlSet00X\Services\intelide  Start = 0
   HKLM\SYSTEM\ControlSet00X\Services\pciide    Start = 0
   ```

هر دو بخش با یک دستور انجام می‌شود (به `ControlSet001` و `ControlSet002` اضافه می‌کند و hiveها را تمیز بارگذاری/آزاد می‌کند):

```powershell
.\scripts\apply_registry_fixes.ps1 -SystemDriveLetter F
```

> روی برد مقصد بررسی کنید: کنترلر SATA باید با کلاس `0101` و درایور IDE *جنریک* بایند شود — نه سرویس `nvata`/`nvgts`/`nvraid` و نه حالت AHCI/RAID.

### شناسایی چیزی که برد شما تشخیص می‌دهد

از هر ویندوزی که روی برد مقصد اجرا می‌شود، دستگاه‌های PCI را لیست کنید و کلاس کد کنترلر SATA را بررسی کنید:

```powershell
wmic path Win32_PnPEntity where "DeviceID like 'PCI%'" get DeviceID, Name /format:list
```

مقادیر مرجع (nForce 720a، حالت IDE/Legacy، تست‌شده در عمل):

```
PCI\VEN_10DE&DEV_0759  -> NVIDIA nForce 720a/730a SATA   (کلاس 0101، کنترلر IDE)
PCI\VEN_10DE&DEV_0AD0  -> NVIDIA nForce 720a PATA        (کلاس 0101، کنترلر IDE)
```

هر دو به درایور جنریک «Standard Dual Channel PCI IDE Controller» (`pci\cc_0101`) بایند می‌شوند و **هیچ** سرویس `nvata`/`nvgts`/`nvraid` وجود ندارد. دقیقاً همین وضعیت است که ورودی CDDB بالا برای آن ساخته شده.

مرجع کلاس کد: `0101` = کنترلر IDE (این راهنما)، `0106` = AHCI، `0104` = RAID. اگر کد `0106`/`0104` دیدید، برد را در بایوس به حالت IDE/Legacy ببرید — این راهنما تزریق درایور AHCI/RAID را پوشش نمی‌دهد.

## مرحله ۵ — فعال‌سازی به روش درست

تغییر سخت‌افزار WPA را به هم می‌ریزد و پیام فعال‌سازی ظاهر می‌شود. دو راه برای حل آن وجود دارد — **فقط یکی دائمی است:**

### روش فایل رجیستری جادویی (استفاده نکنید)

تنظیم `OOBETimer` به مقدار معروف `FFD571D68B6A8D6FD53393FD` همراه با یک `DigitalProductId` «وصله‌شده» **روی این سخت‌افزار پایدار نمی‌ماند** (دو بار تست شد):

1. بوت بعدی → WPA یک `OOBETimer` تازه می‌سازد → وضعیت به حالت قبل برمی‌گردد.
2. اگر کپی داخل hive سیستم (SYSTEM) نیز وصله شود → WPA وضعیت را **corrupted** اعلام می‌کند و سیستم روی صفحه خطا گیر می‌کند.

این مسیر روی بردهای nForce با ساعت CMOS مرده بن‌بست است.

### روش Confirmation ID (دائمی، بدون کرک)

فعال‌سازی تلفنی ویندوز از روی **Installation ID** یک **Confirmation ID** می‌سازد. الگوریتم آن (ریاضیات hyperelliptic curves داخل `licdll.dll`) مهندسی معکوس شده و به‌صورت ابزار متن‌باز پیاده‌سازی شده است. واردکردن یک Confirmation ID معتبر یعنی فعال‌سازی *واقعی* — WPA برای همیشه آن را می‌پذیرد؛ بدون برگشت، بدون پیام و بدون بالون.

1. سیستم را بوت کنید → ویزارد فعال‌سازی **Installation ID** را نشان می‌دهد (۵۴ رقم، ۹ گروه ۶تایی، مثلاً `123456-789012-345678-...`).
2. **Confirmation ID** را با یکی از این ابزارها تولید کنید (متن‌باز؛ روی هاست یا روی خود XP اجرا می‌شود):
   - [Alex313031/xp_activate32](https://github.com/Alex313031/xp_activate32) — گرافیکی، خروجی آماده `.exe` دارد
   - [Endermanch/XPConfirmationIDKeygen](https://github.com/Endermanch/XPConfirmationIDKeygen) — نسخه اصلی
3. Confirmation ID را در ویزارد وارد کنید → **فعال‌سازی دائمی.**

این ابزارها Confirmation ID را **محلی** و از روی Installation ID محاسبه می‌کنند — نه به ماشین XP نیاز دارند و نه به سرورهای مایکروسافت؛ بنابراین روی هاست نیز به‌راحتی کار می‌کنند. دکمه «activate/deposit» داخل GUI فقط روی خود XP کار می‌کند (با `licdll.dll` محلی ارتباط برقرار می‌کند)؛ روی هاست کافی است کد تولیدشده را در ویزارد فعال‌سازی وارد کنید.

فقط برای سیستم‌هایی استفاده کنید که مالک آن‌ها هستید و لایسنس معتبر دارید.

## مرحله ۶ — تمیزکاری

پس از پایدار شدن دستگاه:

- **boot.ini** — فلگ‌های دیباگ باقی‌مانده از مرحله تشخیص را حذف کنید:
  ```powershell
  .\scripts\clean_boot_ini.ps1 -DriveLetter F
  ```
  این اسکریپت `/bootlog` و `/SOS` را حذف و `/fastdetect` و `/usepmtimer` را حفظ می‌کند (مورد دوم مشکل تایمر بردهای nForce/AMD را حل می‌کند).

- **فلگ Dirty** — تا پاک‌شدن این فلگ، chkdsk هنگام هر بوت اجرا می‌شود:
  ```powershell
  .\scripts\check_volume_state.ps1
  chkdsk F: /f        # فقط در صورت گزارش Dirty
  ```

- فایل‌های باقی‌مانده را پاک کنید: `ntbtlog.txt` (فقط وقتی `/bootlog` فعال باشد ساخته می‌شود)، VHDهای تست و موارد مشابه.

- **بررسی نهایی همه‌چیز** با یک دستور:
  ```powershell
  .\scripts\verify_fixes.ps1 -DriveLetter F
  ```

## چک‌لیست پذیرش

قبل از اعلام پایان کار، این موارد را بررسی کنید:

- [ ] بوت VM (دیسک **آفلاین** روی هاست) به دسکتاپ می‌رسد

- [ ] فعال‌سازی: Confirmation ID پذیرفته شد و پس از ریبوت هیچ پیامی نیست
- [ ] هنگام بوت `chkdsk` اجرا نمی‌شود (حجم Dirty نیست)
- [ ] `verify_fixes.ps1 -DriveLetter F` همه بررسی‌ها را پاس می‌کند
- [ ] boot.ini بدون `/bootlog` و `/SOS` است
- [ ] بکاپ بوت‌سکتور تا چند بوت موفق نگه داشته شده

## بازگشت (Rollback)

هر مرحله برگشت‌پذیر است:

- **بوت‌سکتور / BPB** → بازیابی از بکاپ:
  ```powershell
  .\scripts\restore_bootsector.ps1 -DriveLetter F -BackupPath backups\bootsector_<timestamp>.bin
  ```
- **اصلاحات رجیستری** → حذف `ControlSet00X\Control\CriticalDeviceDatabase\pci#cc_0101` و برگرداندن مقادیر `Start` سرویس‌های `intelide`/`pciide` به حالت اولیه (مقادیر قبلی را قبل از اجرای اسکریپت یادداشت کنید).
- **فعال‌سازی** → این یک فعال‌سازی واقعی است و چیزی برای بازگشت ندارد. اگر به‌جای آن از reg-hack استفاده کرده بودید و گیر کرده‌اید، به سوالات پرتکرار مراجعه کنید.

## ضمیمه — اتصال دیسک فیزیکی به VM

برای اینکه XP از روی همان نصب فیزیکی بوت شود، به یک دیسک raw (pass-through) در VM نیاز دارید. دیسک باید به هاست متصل باشد:

**VirtualBox** (به‌عنوان ادمین؛ ابتدا دیسک را آفلاین/آنمونت کنید):

```powershell
VBoxManage internalcommands createrawvmdk `
    -filename "C:\vm\xpdisk.vmdk" -rawdisk \\.\PhysicalDrive<N>
```

سپس `xpdisk.vmdk` را به‌عنوان دیسک SATA/IDE به VM اضافه کنید. در حالی که VM در حال اجراست، اجازه ندهید هاست حجم‌های XP را مونت کند (مرحله ۳).

**VMware Workstation:** فایل توصیف‌گر raw-disk `xpdisk.vmdk` را با هندسه دیسک فیزیکی بسازید:

```
# Disk DescriptorFile
version=1
CID=ffffffff
parentCID=ffffffff
createType="fullDevice"

# Extent description
RW 3907029168 FLAT "\\.\PhysicalDrive<N>" 0

# The Disk Data Base
ddb.virtualHWVersion = "7"
ddb.geometry.cylinders = "<cylinders>"
ddb.geometry.heads = "16"
ddb.geometry.sectors = "63"
```

(اندازه extent و هندسه را با دیسک خودتان هماهنگ کنید: `Get-Disk` + `Get-Partition` اندازه را نشان می‌دهند؛ `heads=16, sectors=63` و `cylinders = size / 512 / 63 / 16`.) سپس `.vmdk` را به VM اضافه کنید.

**Hyper-V:** `Add-VMHardDiskDrive -VMName <vm> -Path \\.\PhysicalDrive<N>` (pass-through).

در همه حالات: VM باید **همان** پارتیشنی را بوت کند که برد واقعی بوت می‌کند. در طول بوت‌های VM، دیسک را روی هاست **آفلاین** نگه دارید (`Set-Disk -Number <N> -IsOffline $true`).

## سوالات پرتکرار

**س: با دیسک آفلاین در VM باز هم 0xED می‌گیرم.**
ج: BPB را وصله بزنید (`patch_bpb_sectors.ps1`). اگر باز هم خطا بود، بررسی کنید که `ntldr`/`NTDETECT.COM` موجودند و مسیر ARC در boot.ini با پارتیشن واقعی یکی است (`partition(1)` و ...).

**س: بوت می‌شود اما پیام «It's now safe to turn off your computer» ظاهر می‌شود.**
ج: این نصب با HAL غیر ACPI («Standard PC») از ماشین قبلی بالا آمده است. تعویض HAL به ACPI از نظر تئوری ممکن است، اما روی این بیلد سبک‌شده حتی با `hal.inf` و ترفندهای `/hal=` و `/kernel=` در boot.ini خطای Blue Screen داد؛ به همین دلیل عمداً در این راهنما پوشش داده نشده است. سیستم به‌درستی کار می‌کند؛ فقط نمی‌تواند خودکار خاموش شود.

**س: آیا پیام فعال‌سازی برمی‌گردد؟**
ج: با Confirmation ID واقعی — خیر. نکته مرحله ۵ دقیقاً همین است: WPA یک فعال‌سازی معتبر ذخیره می‌کند.

**س: هنگام هر بوت chkdsk اجرا می‌شود.**
ج: فلگ Dirty — مرحله ۶.

**س: آیا روی برد AHCI/RAID کار می‌کند؟**
ج: وصله رجیستری برای حالت IDE/Legacy است (کلاس 0101). برای AHCI باید درایور AHCI برد داخل نصب تزریق شود که داستان سخت‌تری است.

**س: برد من nForce نیست؛ اینتل یا AMD است.**
ج: مراحل به چیپ‌ست وابسته نیستند؛ فقط نکته `/usepmtimer` و جزئیات ورودی CDDB فرق می‌کند (کلاس کد کنترلر خودتان را بررسی کنید).

**س: اول reg-hack (OOBETimer/DPID) را امتحان کردم و حالا XP روی صفحه خطای فعال‌سازی گیر کرده است.**
ج: هک را برگردانید: hiveها را از بکاپ قبل از هک بازیابی کنید (یا `DigitalProductId`/`OOBETimer` را به مقادیر اصلی برگردانید و `wpa.dbl` را حذف کنید)، یک بار بوت کنید تا WPA وضعیت تمیز بسازد و سپس از مسیر Confirmation ID در مرحله ۵ بروید. با ماشین وضعیت نجنگید — آن را با یک فعال‌سازی واقعی جایگزین کنید.

**س: حتی بعد از فعال‌سازی، بالون «your Windows is not genuine» ظاهر می‌شود.**
ج: این WGA است؛ بررسی جداگانه‌ای روی کلید محصول (نه وضعیت WPA). با `MGADiag.exe` مایکروسافت (ابزار امضاشده) بررسی کنید. با فعال‌سازی واقعی و کلید OEM قانونی معمولاً خودش برطرف می‌شود؛ اگر ماند، کلید خودش در لیست مسدود است و فقط یک کلید مجاز دیگر آن را حل می‌کند.

**س: آیا keygen باید روی خود ماشین XP اجرا شود؟**
ج: نه — Confirmation ID به‌صورت محلی و از روی Installation ID روی هر ویندوزی محاسبه می‌شود. فقط دکمه «activate/deposit» داخل GUI به XP نیاز دارد (در `licdll.dll` محلی می‌نویسد)؛ به همین سادگی می‌توانید کد تولیدشده را در ویزارد فعال‌سازی وارد کنید.

**س: نمی‌دانم برد من در چه حالتی SATA است.**
ج: کوئری wmic از مرحله ۴ را روی برد اجرا کنید: کلاس `0101` = IDE/Legacy (این راهنما پاسخ می‌دهد)، `0106` = AHCI (نیاز به تزریق درایور — پوشش داده نشده)، `0104` = RAID (پوشش داده نشده).
